# 0012 Package layout, API docs and release

Status: accepted, 2026-10-04

## Context

The brief wants an ng-packagr build with a `/devtools` secondary entry point, a working `npm pack`, API docs from TypeDoc deployed with the demo, and release tooling with changesets. Publishing waits for Adrian. The npm name `signal-timeline` returned 404 on the registry on 2026-10-04, so it is free; Adrian still confirms it.

## Decision

- Library project `signal-timeline` at `projects/signal-timeline`. The secondary entry point is `projects/signal-timeline/devtools` with its own `ng-package.json`, so ng-packagr derives the subpath `signal-timeline/devtools`. The main entry exports the store feature, the group, the persistence adapters, the replay helpers and the public types. The patch engine and the tree are internal; only the `Patch` and `Operation` types are public, because entries expose them.
- `package.json` of the library: `sideEffects: false`, `exports` generated by ng-packagr, peers as in ADR 0002, `rxjs` as a peer, `tslib` as the only dependency.
- `publint` and `@arethetypeswrong/cli` run on the tarball in CI, next to `npm pack`.
- TypeDoc 0.28.20 documents both entry points and writes to `docs/api`. The Pages build puts the demo at `/` and the API at `/api/`. Only public API carries TSDoc; the repo has no other comments.
- Changesets 3.0.3 with `@changesets/changelog-github`. The library's source `package.json` sets `publishConfig.directory` to the ng-packagr output so that `pnpm publish`, which changesets uses under pnpm, publishes `dist/signal-timeline` and not the source folder. The release workflow builds the tarball with the previous toolchain line (ADR 0002) first. If `publishConfig.directory` does not behave under pnpm 12 with changesets, the release script runs `changeset version`, builds, and publishes from `dist` by hand; the PLAN note records which one worked.
- Three workflows are written and checked locally with the same commands: `ci.yml`, `pages.yml`, `release.yml`. None of them is run or deployed from here, and `act` is not installed.

## Alternatives

- Publish from the source folder: ships uncompiled TypeScript.
- Release with a hand-written script only: loses the changelog and the version PRs.
- Separate packages for core and devtools: the brief asks for a secondary entry point.

## Consequences

- Both entry points share one version and one changelog.
- Adrian has to add an `NPM_TOKEN` secret, create the repo and push before any workflow runs. The final report lists the commands.
