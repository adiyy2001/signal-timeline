# 0017 Recording the demo GIF

Status: accepted, 2026-10-04

## Context

The README needs a demo GIF of the vector editor, recorded with Playwright and converted with ffmpeg, under 8 MB. The story: draw a few shapes, undo, make a different change to create a branch, open the tree, jump between branches, scrub the timeline.

## Decision

- `tools/record-demo.mjs` (`pnpm demo:gif`) serves the production build of the demo with the same server the end-to-end tests use, drives it in Google Chrome through `playwright-core` with video recording on, and writes `docs/media/demo.gif`. The script fails when the file is larger than 8 MB.
- The video is webm at 1280 by 720. ffmpeg converts it at 12 frames per second, scaled to 960 pixels wide, with a 96 colour palette generated from the whole clip (`palettegen` with `stats_mode=diff`, `paletteuse` with Bayer dithering). That keeps flat UI colours clean and the file small.
- Headless Chrome does not draw a mouse pointer, so a small red dot follows the mouse events through an init script. Without it the drags look like shapes appearing on their own.
- The script drives the same controls a user would: tool buttons, drags on the canvas, the undo button, a click on a tree item, and the arrow keys on the scrubber. It sleeps between steps so a viewer can read the label that changed.
- The GIF is committed under `docs/media/`. It is regenerated by running the script, so it cannot drift from the UI without anyone noticing.

## Alternatives

- Record a real screen: needs a display session and a cursor, and cannot be rerun in CI or in a container.
- An animated WebP or MP4: smaller, but GitHub does not play either of them inline in a README the way it does a GIF.
- A GIF made from screenshots: no motion between states, and the scrubber would not look like a scrubber.

## Consequences

- The recording depends on the demo's labels (`Add connector`, `Add Rectangle 2`) and on the canvas coordinates. A change to either breaks the script loudly, not silently.
- The GIF is a binary in git history. Replacing it adds its size again, so it is replaced only when the UI changes in a way a reader would notice.
